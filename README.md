# Telegram AI - Dark API + Bothost

Обычный аккаунт Telegram участвует только в разрешённых группах. Это отдельный проект, не Bao Cards. По умолчанию используется deepseek-v4-pro через https://darkapi.shop/v1. Имена и совместимость Dark API взяты из предоставленной инструкции сервиса; реальный запрос разработчиком не выполнялся.

## 1. Подготовка на Windows

1. Установи Python 3.11 или новее с python.org, включив Add Python to PATH.
2. Распакуй архив. Рабочая папка - github-upload, в ней лежит main.py.
3. Открой эту папку, набери powershell в адресной строке Проводника и нажми Enter.
4. Выполни:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

При обновлении существующего проекта не выполняй Copy-Item поверх заполненного .env. Сохрани старую папку data, поменяй параметры вручную. В этой версии MISTRAL_API_KEY/MISTRAL_MODEL заменены на AI_API_KEY/AI_MODEL.

Заполни TELEGRAM_API_ID и TELEGRAM_API_HASH данными своего приложения Telegram. В AI_API_KEY вставь новый ключ Dark API. Ранее опубликованный ключ отзови в кабинете провайдера. Остальное пока оставь:

```dotenv
AI_BASE_URL=https://darkapi.shop/v1
AI_MODEL=deepseek-v4-pro
```

В .env значения записываются после =, без угловых скобок. Не присылай ключи и строку сессии в чат.

## 2. Войти в Telegram и узнать ID группы

Заранее добавь отдельный аккаунт в нужную группу. Останови другие копии программы с этим аккаунтом. На компьютере выполни:

```powershell
.\.venv\Scripts\python.exe login.py
```

Введи номер телефона с кодом страны, код входа и пароль двухэтапной проверки, если он включён. Используется аккаунт, не токен BotFather. При вводе пароля символы могут не отображаться.

Скрипт покажет ID аккаунта и групп, сохранит data/account.session и session_string.txt. Если вход ранее выполнен и сессия действительна, повторный код не нужен.

В .env заполни ALLOWED_CHAT_IDS отрицательным числом из списка, например -1001234567890. Для нескольких групп перечисли числа через запятую. OWNER_ID можно оставить пустым: управление доступно через Избранное самого ИИ-аккаунта. Для управления со своего другого аккаунта укажи его числовой ID.

## 3. Проверить API и запуск на компьютере

```powershell
.\.venv\Scripts\python.exe check_api.py
```

Это один настоящий запрос с расходом токенов. В Telegram ничего не отправляется. При AI HTTP 401 проверь ключ, при 402 баланс/тариф, при 403 доступ, при 404 адрес и модель, при 429 лимиты сервиса. Точный смысл кода зависит от провайдера.

Затем:

```powershell
.\.venv\Scripts\python.exe main.py
```

С другого аккаунта напиши в разрешённой группе: бао привет. Свои исходящие сообщения ИИ-аккаунт не обрабатывает. Ответ может быть пропущен из-за интервала, лимита или решения модели промолчать.

В Избранном ИИ-аккаунта напиши !ai status. После локальной проверки останови программу Ctrl+C перед запуском на хосте.

## 4. Загрузить на GitHub

1. На github.com нажми +, New repository. Название: telegram-chat-ai.
2. Выбери Public для простого подключения к Bothost или Private с отдельной настройкой доступа на хосте. Сам код не содержит ключей.
3. Создай репозиторий. Открой uploading an existing file или Add file, Upload files.
4. Загружай исходные файлы из github-upload прямо в корень репозитория, не ZIP и не внешнюю папку. Обязательно main.py, config.py, brain.py, storage.py, instance.py, login.py, check_api.py, personality.txt, requirements.txt, README.md, .env.example, .gitignore; tests можно тоже загрузить.
5. Не загружай созданные тобой .env, session_string.txt, data и .venv. При загрузке через браузер .gitignore не скрывает их автоматически.
6. Нажми Commit changes. Убедись, что main.py и requirements.txt видны сразу в корне.

Если репозиторий уже есть, замени одноимённые исходники, сохрани секреты только локально/в хостинге. Старую базу данных не заменяй.

## 5. Запуск на Bothost

1. Открой bothost.ru и создай отдельный проект для этого аккаунта. Не заменяй им Bao Cards.
2. Укажи ссылку на GitHub-репозиторий и его ветку, обычно main.
3. Выбери Python и Telethon/userbot, если такая опция есть. Главный файл main.py. Команда запуска, если поле есть: python main.py. Зависимости: requirements.txt. Специальный Dockerfile этому проекту не нужен.
4. Приложение не использует BOT_TOKEN. Если форма принудительно требует токен BotFather, используй раздел/инструкцию Telegram Userbot или уточни у поддержки хостинга, как создать такой проект.
5. До рабочего запуска задай переменные окружения в настройках проекта:

| Имя | Значение |
| --- | --- |
| TELEGRAM_API_ID | Твой API ID Telegram |
| TELEGRAM_API_HASH | Твой API Hash Telegram |
| SESSION_STRING | Вся строка из session_string.txt, без кавычек и переносов |
| AI_API_KEY | Новый ключ Dark API |
| AI_BASE_URL | https://darkapi.shop/v1 |
| AI_MODEL | deepseek-v4-pro |
| ALLOWED_CHAT_IDS | ID нужной группы, с минусом |
| DATA_DIR | /app/data |
| OWNER_ID | ID твоего управляющего аккаунта, необязательно |
| BOT_NAME | Бао |
| TRIGGER_WORDS | бао |
| RANDOM_REPLY_CHANCE | 0.03 |
| MIN_REPLY_SECONDS | 90 |
| DAILY_API_LIMIT | 100 |

Остальные параметры берутся по умолчанию из кода. Не загружай заполненный .env на GitHub. SESSION_STRING даёт доступ к аккаунту, храни её как пароль.

6. Сохрани переменные и запусти/перезапусти проект. Если код обновлён в GitHub, выполни обновление из Git/повторное развёртывание в Bothost: обычный рестарт может запускать старый код.
7. В логах должно появиться: Запущен. Разрешённых групп: 1. На хостинге не запускай login.py.
8. Проверь !ai status и сообщение бао привет с другого аккаунта в группе.

Bothost документирует StringSession для входа без терминала и /app/data для сохранения базы между обновлениями:
- https://www.bothost.ru/docs/telegram-userbot-setup
- https://bothost.ru/docs/database-storage
- https://bothost.ru/docs/getting-started
- https://bothost.ru/docs/git-repository-access

Для приватного репозитория подключи его в разделе Bothost «Git репозитории» через deploy key или токен с доступом только к нужному репозиторию. Публичному репозиторию такой доступ не нужен.

Если переносишь память с компьютера, останови обе копии и загрузи data/memory.sqlite3 в /app/data/memory.sqlite3 через файловый менеджер хоста. Не запускай две копии с одной сессией одновременно.

## 6. Управление

Команды отправляются в Избранное ИИ-аккаунта либо ему в ЛС от OWNER_ID. Вместо CHAT_ID подставляй отрицательный ID группы.

```text
!ai help
!ai status
!ai announce CHAT_ID
!ai pause CHAT_ID
!ai resume CHAT_ID
!ai remember CHAT_ID шутка и её смысл
!ai memories CHAT_ID
!ai forget CHAT_ID ID_ЗАПИСИ
!ai nick CHAT_ID USER_ID прозвище
!ai clear CHAT_ID CONFIRM
```

announce объясняет участникам работу ИИ и передачу контекста внешнему API. nick сохраняет прозвище в памяти ИИ, не меняет настоящее имя в Telegram. Обучения весов модели здесь нет: используется недавний контекст и вручную сохранённая память. Участники могут исключить свои сообщения командой /ai_forgetme и вернуть обработку /ai_allowme. Уже отправленные провайдеру данные это не удаляет.

Характер меняется в personality.txt, после изменения перезапусти проект. Контекст по умолчанию 35 сообщений, хранение 7 дней. С 01:00 до 09:00 по Москве случайные ответы выключены, обращения работают. QUIET_START=0 и QUIET_END=0 отключают тихие часы. MIN_REPLY_SECONDS - интервал между попытками ответа в каждой группе; DAILY_API_LIMIT - общий лимит запросов в сутки, а не денежных затрат. 0.03 означает 3% шанс случайного ответа на новое сообщение, это не таймер самостоятельных сообщений.

## Обновления и ошибки

- Изменил Python-файлы: обнови GitHub и запусти обновление из Git на Bothost.
- Изменил переменные хоста: сохрани и перезапусти.
- Не авторизован: создай session_string.txt локально и обнови SESSION_STRING.
- Не видит группу: аккаунт должен быть участником, проверь отрицательный ID.
- AI HTTP ...: проблема запроса к провайдеру, а не Telegram. Ключ в логи не выводится.
- FloodWait: Telegram требует паузу, программа временно пропускает ответы.
- AuthKeyDuplicated: останови все копии и создай новую сессию локально.
- Пауза сохраняется в базе: включи !ai resume CHAT_ID.

## Проверка разработчиком

Офлайн-тесты проверяют память, лимиты, блокировку экземпляров и API-запрос на подставном HTTP-транспорте. Реальный Dark API и Telegram не вызывались. Полный запуск на твоём аккаунте проверяется шагами выше.
